Blog publishing desk

Create or update a public article through the repository’s protected publishing workflow. GitHub verifies administrator access before the workflow can write anything.

Open the publishing workflow ↗

How publishing works

  1. Sign in to GitHub with an owner or repository administrator account.
  2. Open Actions → Publish or update a blog article → Run workflow on the master branch.
  3. Choose publish or update, add the article title, URL slug, summary, category and Markdown content.
  4. Optionally provide an existing image path under /assets/img/. Images must already be in the repository.
  5. The workflow validates the article and full Jekyll site, writes the article and sitemap entry, then starts the normal Pages deployment.
Access: the public site is read-only. Only repository administrators can run this publisher; readers cannot create or edit site content. Published articles are public.
Existing URLs: legacy blog URLs are protected. New articles receive /blogs/<slug>.html URLs. Use the same slug and choose Update only for articles created by this publisher.

Writing checklist

  • Use clear headings and short paragraphs; Markdown is supported.
  • Choose a descriptive summary between 40 and 180 characters.
  • Use only images already available in /assets/img/.
  • Do not include secrets, private customer data or unsupported performance claims.
